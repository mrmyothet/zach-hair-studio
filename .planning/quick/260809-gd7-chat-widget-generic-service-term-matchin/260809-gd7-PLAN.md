<objective>
Fix `findMatchingService` in `landing-page/lib/chat.ts` so generic service terms ("haircut", "hair cut", "cut") match the seeded "Precision Cut" service (category "Cuts"), not just its exact name/slug. Today a message like "I want get Hair Cut today" never matches any service and falls through past the availability-check branch straight to the generic fallback reply, even though "today" is a parseable date.

Purpose: the chat widget's core value is routing real availability questions to `checkAvailabilityReply`; generic phrasing is the common case for a walk-in-style request and currently defeats matching entirely.

Output: `findMatchingService` also matches a service's `category` (lowercased) and a small static category-alias map (e.g. `cuts: ["cut", "haircut", "hair cut"]`), plus one runnable self-check script proving the fix and guarding against regressions (exact name/slug matching, no false-positive on "cute").
</objective>
