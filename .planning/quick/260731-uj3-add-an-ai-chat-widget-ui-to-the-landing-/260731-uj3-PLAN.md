  <action>
Create a new module with no React imports — pure TypeScript, importable from a client component.

Import `type { Service }` from `@/lib/services` and `formatDuration` from `@/lib/formatDuration`.

Export these four public symbols:

1. `ChatRole` — a union type of the two literals for user and assistant turns.
2. `ChatMessage` — an object type with `id: string`, `role: ChatRole`, `text: string`.
3. `STARTER_PROMPTS` — a readonly string array of four booking-assistant openers, e.g. asking what services are offered, how much a haircut costs, what the opening hours are, and a request to book an appointment.
4. `createMessage(role: ChatRole, text: string): ChatMessage` — builds a `ChatMessage` using a module-scoped incrementing counter for the `id` (do NOT use `crypto.randomUUID` or `Date.now`; a counter is deterministic and avoids any SSR/hydration id mismatch).
5. `sendChatMessage(userText: string, history: ChatMessage[], services: Service[]): Promise<string>` — resolves to the assistant's reply text.

`sendChatMessage` body (the ONLY thing a future real backend replaces):
- Add a head comment stating this function is the single swap point: its body becomes a `fetch` to the chat API while the signature and return type stay identical. `history` is accepted now but unused by the mock so the future request payload needs no call-site change.
- `await` a `new Promise` wrapped `setTimeout` of a module constant `MOCK_REPLY_DELAY_MS = 600` to simulate latency.
- Normalize input once: lowercase + trim into a local const.
- Format prices with a module-level `Intl.NumberFormat("en-US", { style: "currency", currency: "USD", maximumFractionDigits: 0 })` — same shape Contact.tsx uses.

Matching cascade, first hit wins:
  a. **Service name match** — find the first service (iterating `services` sorted by `displayOrder`) whose lowercased `name` or `slug` (with hyphens normalized to spaces) is contained in the normalized input. Reply naming the service, its formatted price, `formatDuration(durationMinutes)`, and its `shortDescription`, ending with a link built as `[Book {name}](/book?service={slug})`.
  b. **book / appointment / schedule** — nudge toward the booking flow, ending with a `[...](/book)` link.
  c. **price / cost / how much** — list the first three services by `displayOrder` as `name — price`, then a `[...](/book)` link.
  d. **hour / open / close** — reply with the salon hours string `Open Daily: 9:00 AM – 7:30 PM` (declare it as a module const with a short comment that it mirrors the copy in Contact.tsx), plus a `[...](/book)` link.
  e. **service / offer / do you do** — list every service name by `displayOrder`, plus a `[...](/book)` link.
  f. **fallback** — a friendly booking-assistant catch-all that states what it can help with (services, pricing, hours, booking) and ends with a `[...](/book)` link.

Guard for an empty `services` array (the catalog fetch fails soft to `[]`): branches a, c, and e must degrade to a sensible reply that still offers the `/book` link rather than producing an empty list.

Document the link contract in a head comment: assistant replies may embed `[label](/relative-path)` and ONLY site-relative paths beginning with `/` are ever emitted — the renderer in ChatWidget relies on this to refuse absolute or scheme-bearing URLs.

**Part B — `landing-page/components/ChatWidget.tsx` (new):**

`"use client"` at the top. Default-export `ChatWidget({ services }: { services: Service[] })`.

*Component placement (important):* define `MessageBubble`, `TypingIndicator`, `StarterChips`, and the link renderer as **module-scope** function components/helpers above the default export — exactly where `Navbar.tsx` puts `Logo()`. Do NOT nest them inside `ChatWidget`'s body: a nested component gets a fresh identity every render, which remounts the subtree and destroys input focus on every keystroke. The launcher button and the panel shell stay as inline JSX inside `ChatWidget`'s return so they can read state directly.

State (`useState` only, no external state library): `open: boolean`, `messages: ChatMessage[]`, `input: string`, `isTyping: boolean`.

Refs: `messageListRef` (scroll container), `inputRef` (text input), `launcherRef` (launcher button).

Effects:
- On `messages` / `isTyping` change and while `open`: set `messageListRef.current.scrollTop = scrollHeight` so the newest turn is visible.
- When `open` flips true: focus `inputRef.current`.
- While `open`: attach a `keydown` listener on `window` that closes the panel on Escape and calls `launcherRef.current?.focus()`. Return the removal function from the effect.

`handleSend(overrideText?: string)`:
1. Resolve the text from `overrideText ?? input`; return early if it trims to empty or if `isTyping` is already true.
2. Append `createMessage("user", text)` to `messages`, clear `input`, set `isTyping` true.
3. In a try block, `await sendChatMessage(text, messages, services)` and append `createMessage("assistant", reply)`.
4. In catch, append an assistant message with a graceful fallback apologizing and pointing at the booking page.
5. In finally, set `isTyping` false and refocus the input.

Wiring: the form's `onSubmit` (preventDefault) calls `handleSend()`; the input's `onKeyDown` sends on Enter without Shift (also preventDefault); each starter chip's `onClick` calls `handleSend(prompt)`.

Link rendering inside `MessageBubble` — security-relevant, follow exactly: split the message text with the regex `/\[([^\]]+)\]\((\/[^)\s]*)\)/g`. The href group is anchored to a literal leading slash so only site-relative paths can ever match; anything else stays inert plain text. Render each match as a `next/link` `<Link>` with `className="text-gold underline underline-offset-2"` and every non-matching segment as plain text. Give every produced node a stable `key` from its segment index. Never build the href by concatenating unvalidated input, and never use `dangerouslySetInnerHTML`.

Starter chips render only while `messages.length === 0`, mapping `STARTER_PROMPTS` to pill buttons: `border border-gold/20 hover:border-gold text-gray-300 hover:text-gold rounded-full px-3 py-1.5 text-xs transition-colors`.

Accessibility:
- Launcher: `type="button"`, `ref={launcherRef}`, `aria-label` describing the booking assistant, `aria-expanded={open}`, and it swaps `ChatBubbleIcon` for `CloseIcon` when open.
- Panel: `role="dialog"`, `aria-modal="true"`, `aria-label` naming the assistant.
- Message list container: `aria-live="polite"`.
- Header close button: `type="button"` with its own `aria-label`, rendering `CloseIcon`.
- Send button: `type="submit"`, `aria-label`, disabled when `isTyping` or the trimmed input is empty.

Styling (theme classes from globals.css only):
- Launcher: `fixed bottom-6 right-24 w-14 h-14 bg-gold hover:bg-gold-dark text-charcoal rounded-full shadow-lg flex items-center justify-center transition-all duration-300 z-40`. The `right-24` offset is what keeps it clear of BackToTop's `right-6` — do not change it.
- Panel: `fixed z-50` with mobile-first near-full-screen (`inset-x-4 bottom-24 top-24`) and desktop overrides (`sm:inset-x-auto sm:top-auto sm:right-6 sm:w-96 sm:h-[32rem] sm:max-h-[70vh]`), plus `bg-charcoal border border-gold/20 rounded-2xl shadow-2xl flex flex-col overflow-hidden`.
- Header: `border-b border-gold/20` bar with the title in `font-serif text-gold` and the close button on the right.
- Message list: `flex-1 overflow-y-auto px-4 py-4 space-y-3`.
- User bubble: `bg-gold text-charcoal rounded-2xl rounded-br-sm`, container right-aligned. Assistant bubble: `bg-charcoal-light border border-white/10 text-gray-200 rounded-2xl rounded-bl-sm`, container left-aligned. Both `max-w-[85%] px-3.5 py-2.5 text-sm leading-relaxed whitespace-pre-line`.
- `TypingIndicator`: three `w-1.5 h-1.5 bg-gold/70 rounded-full animate-bounce` dots with staggered inline `animationDelay` values; rendered only while `isTyping`.
- Input row: `border-t border-white/10 p-3 flex items-center gap-2`; the text input reuses Contact.tsx's input class string (adjusted to `py-2.5`); the send button is a gold circle `w-10 h-10 bg-gold hover:bg-gold-dark text-charcoal rounded-full ... disabled:opacity-40 disabled:cursor-not-allowed`.

Add no npm dependency — this repo has zero markdown, icon, or animation packages and must stay that way.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-UJ3-01 | Tampering | `MessageBubble` link renderer in `ChatWidget.tsx` | high | mitigate | Link regex anchors the href group to a literal leading `/` (`\((\/[^)\s]*)\)`), so `javascript:`, `data:`, and absolute cross-origin URLs never become an href and stay inert text. Renders via `next/link`; `dangerouslySetInnerHTML` is not used anywhere. |
| T-UJ3-02 | Information disclosure | `sendChatMessage` reply content | medium | mitigate | Replies are built only from the public `Service` catalog fields already rendered on the homepage (name, slug, price, duration, shortDescription). No booking, client, or auth data is reachable from this module. |
| T-UJ3-03 | Denial of service | `handleSend` in `ChatWidget.tsx` | low | mitigate | Send is guarded on `isTyping` and on empty/whitespace input, and the send button is disabled in both states, so rapid clicks cannot stack pending timers. Local-only state; no server load. |
| T-UJ3-04 | Spoofing | Mock assistant persona | low | accept | Replies are canned local strings presented as a salon assistant; no claim of human identity and no credential collection. Acceptable for a UI-only mock. |
| T-UJ3-SC | Tampering | npm install surface | high | mitigate | Zero new dependencies — no markdown, icon, or animation package. `landing-page/package.json` and the lockfile must be unchanged after this task; the package-legitimacy gate is therefore not triggered. |
