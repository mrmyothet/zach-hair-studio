## Resolved since the previous audit

### SHOP-02 — Stripe success redirect (`5cebf63`)

`StripePaymentProvider.BuildSuccessUrl` now appends explicit `orderId={id}` and retains `{CHECKOUT_SESSION_ID}`. The success page accepts only explicit numeric `orderId`/`order`; the unsafe trailing-digit regex over random `cs_*` ids is gone.

Focused verification: `StripeSuccessUrlTests` — **3 passed**.

### ACCT-06 — anonymous order IDOR (`674806e`)

`GET /api/orders/{id}` remains anonymous for guests but now requires `?session=` and matches it against `Order.StripeSessionId`; missing, blank, or mismatched values return the same 404. Authenticated clients already use owner-scoped `GET /api/account/orders/{id}`.

Focused verification: `OrderReadScopingTests` — **4 passed** (correct session 200; wrong/missing/blank 404).

### SHOP-05 / LAUNCH-04 — webhook retry signal (`c1530ad`)

A transient `NotFound` fulfillment miss now returns 503 so Stripe retries. Terminal state failure returns 200 plus `LogError` because no redelivery can repair it. Success and idempotent redelivery remain 200.

Focused verification: all `StripeWebhook*` tests — **6 passed**.
