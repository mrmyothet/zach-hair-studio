## Critical gaps

### 1. SHOP-02 — Stripe success redirect cannot resolve the order (BLOCKER)

`StripePaymentProvider.cs:26-28` sends only `?session_id={CHECKOUT_SESSION_ID}`. `landing-page/app/checkout/success/page.tsx:38-42` resolves the order with:

```ts
const match = session.match(/(\d+)$/);
if (match) return Number(match[1]);
```

That heuristic targets `FakePaymentProvider`'s `fake-{orderId}`. A real id is `cs_test_` + ~58 random alphanumerics — it ends in a digit only ~30% of the time, and those digits bear no relation to the order id. A paid guest therefore gets a 404, or **someone else's order rendered**. `ClientReferenceId` is set on the session but never placed in the URL, and no lookup-by-session endpoint exists.

**Why UAT test 8 passed anyway:** in dev/Testing the container binds `FakePaymentProvider` (`Program.cs:107-109`), whose session id *is* `fake-{orderId}`, so the regex works. The automated suite doesn't catch it either — `StripeWebhookTests.cs` uses the hand-made id `cs_test_paid_1`, which conveniently ends in a digit. The green result reflects the fake provider, not Stripe.

**Smallest fix:** append the order id in `StripePaymentProvider.cs:26-28` — `?orderId={request.OrderId}&session_id={{CHECKOUT_SESSION_ID}}`. The page already prefers `orderId` (`page.tsx:33-36`); then delete the regex branch.

### 2. ACCT-06 — `GET /api/orders/{id}` is anonymous and unscoped (BLOCKER, security)

`OrdersController.cs:161` carries no `[Authorize]` and no ownership check; `OrdersService.GetByIdAsync` (`OrdersService.cs:269-277`) filters on id alone and returns `Email`, `CustomerName`, and line items (`OrderExtensions.cs:44-60`). Anyone can walk `/checkout/success?orderId=1..N` and harvest every customer's PII. Blocker 1's regex makes accidental cross-order disclosure a live path, not just a theoretical one.

**Fix that closes both:** require the session id as a second factor — `GET /api/orders/{id}?session={stripeSessionId}` compared against `Order.StripeSessionId`.

### 3. Phase 6 unverified

No `06-VERIFICATION.md`. UAT is not a substitute for goal-backward verification, and the UAT in question passed a test that source inspection shows is broken.
