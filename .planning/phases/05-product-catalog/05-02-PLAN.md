## Phase Goal

**As a** client, **I want to** browse a curated, stylist-recommended product catalog tied to the services I care about, **so that** I can find products my stylist actually recommends without wading through a general storefront.

> Frontend vertical — the visible half of the phase goal. Consumes Plan 05-01's live API to deliver the public `/products` catalog, `/products/[slug]` detail pages, and the "Recommended Products" section on the existing service detail page. After this plan a real client can browse the curated catalog and see stylist-recommended products on any service page — the phase's three success criteria are all observable in the browser.

<objective>
Build the shared frontend data layer (`lib/products.ts` with Zod schemas, mirroring `lib/services.ts` exactly) and the two public catalog routes as React Server Components (PROD-01/02), then extend `ServiceSchema` and the existing `/services/[slug]` page with a "Recommended Products" section (PROD-03) fed by Plan 05-01's extended `ServiceResponseDto`. Add the "Products" nav link per D-04.

Purpose: Make the entire Product Catalog + Recommendations experience real and browsable, closing out all three phase requirements end-to-end.
Output: `/products` list page (category-grouped, empty/out-of-stock states), `/products/[slug]` detail page (404-safe), a shared Zod-validated `lib/products.ts`, an extended `ServiceSchema`/`/services/[slug]` page with the omit-when-empty "Recommended Products" section, and a new "Products" nav link.
</objective>
