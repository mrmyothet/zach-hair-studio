## Phase Goal

**As a** client, **I want to** browse a curated, stylist-recommended product catalog tied to the services I care about, **so that** I can find products my stylist actually recommends without wading through a general storefront.

> Backend vertical — the API half of the phase goal. Delivers the full server-side contract for all three requirements: `Product` entity + read-only endpoints (PROD-01/02) and the `ServiceRecommendedProduct` curation join feeding an extended service-detail response (PROD-03). Plan 05-02 wires this into the browsable UI.

<objective>
Clone `Features/Services/` into a new read-only `Features/Products/` feature (Product entity, DTOs, extension mapper, FluentValidation validator per D-15), add the `ServiceRecommendedProduct` many-to-many join entity (D-11), wire both into `BookingDbContext` with `HasData` seed rows, apply the `AddProducts` migration, then implement `ProductsService`/`ProductsController` (GET list/detail only) and extend `ServicesService.GetBySlugAsync`/`ServiceResponseDto` to surface curated recommendations.

Purpose: Make the entire Product Catalog + Recommendations API contract real, tested, and queryable before any UI is built against it.
Output: `ProductsService`, `ProductsController`, `ServiceRecommendedProduct` join entity, `AddProducts` migration (Product + ServiceRecommendedProduct schema + seed data), and an extended `ServiceResponseDto.RecommendedProducts`.
</objective>
