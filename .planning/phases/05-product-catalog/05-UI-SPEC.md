# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope: `landing-page/` only (PROD-01..03) — a `/products` catalog page, `/products/[slug]` detail
pages, and a new "Recommended Products" section on the existing `/services/[slug]` detail page. This
is a **read-only extension** of the already-established hand-rolled Tailwind system from Phase 1
(`Services.tsx`, `/services` list, `/services/[slug]` detail) — no design system reset, no new
dependency, no cart/checkout UI (that's Phase 6).

## Spacing Scale

Declared values (must be multiples of 4), identical to Phase 1/2 — no exceptions needed for a
read-only catalog:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, badge inline padding |
| sm | 8px | Compact spacing (eyebrow-to-title `mb-3`, dt/dd row internal gaps) |
| md | 16px | Card grid gaps (`gap-4` on tight rows), stock-badge/category-badge padding |
| lg | 24px | Card padding (`p-7`, matches `ServiceCard`), grid gaps (`gap-6`) |
| xl | 32px | Two-column detail-page gap (`gap-8`, matches `app/services/[slug]/page.tsx`) |
| 2xl | 48px | Space between the "Recommended Products" section and the existing service description above it |
| 3xl | 64px | Page section vertical padding (`py-16`, matches `/services`) |

Exceptions: none. No new touch-target minimums are introduced — every interactive element this phase
adds is a full-card `<Link>` (already ≥44px tall by virtue of card padding), matching `ServiceCard`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#181410` (`bg-charcoal`) | Page background, product cards (mirrors `ServiceCard`'s `bg-charcoal`) |
| Secondary (30%) | `#241c15` (`bg-charcoal-light`) | Page `<main>` wrapper background, section backgrounds (mirrors `/services` and homepage `Services` section) |
| Accent (10%) | `#d4af6a` (`text-gold` / `bg-gold`) | See "Accent reserved for" below |
| Destructive | not used this phase | No destructive action exists (read-only browsing); "Out of Stock" uses a neutral/muted treatment, not the red destructive role, since it's informational, not an error (see below) |

**Accent reserved for** (explicit list — nothing else may use gold):
1. Category eyebrow label on cards and detail pages (`text-gold text-xs uppercase tracking-widest`, exact reuse of `service.category` styling)
2. Price amount (`text-gold font-bold`, exact reuse of `Services.tsx`/`ServiceCard`'s price treatment)
3. Card hover border (`hover:border-gold/30`, exact reuse of `card-hover` class already defined in `globals.css`)
4. "Back to products" / breadcrumb link (`text-gold text-xs uppercase tracking-wider hover:underline`, exact reuse of the existing "&larr; Back to services" link)
5. "Recommended Products" section eyebrow/heading treatment on the service detail page, reusing `SectionHeading`'s existing gold eyebrow + `gold-gradient` highlight span

Never use gold for: the "Out of Stock" badge, body copy, or any element not in this list.

**Out of Stock badge (new, this phase):** `bg-white/5 border border-white/10 text-gray-400 text-xs uppercase tracking-wider px-3 py-1 rounded-full` — a muted neutral pill, not a destructive-red badge, since zero stock is informational display-only state in this phase (D-06: no transactional consequence until Phase 6's checkout).

## Additional Notes — Product Component Patterns

**Product card** (`ProductCard`, new): direct structural clone of `ServiceCard` from
`app/services/page.tsx` — `bg-charcoal border border-white/5 hover:border-gold/30 rounded-2xl p-7`
wrapped in a `<Link href="/products/{slug}">`. If `imageUrl` is present, render it at the top of the
card (`aspect-video w-full rounded-xl object-cover mb-5`, matching the detail page's `Image` usage);
if absent, fall back to the existing "Z" monogram badge (`w-14 h-14 bg-gold/10 rounded-xl` with the
serif "Z") exactly as `ServiceCard` does today — do not invent a new placeholder pattern. Category
eyebrow, name (`h3 text-lg font-semibold`), short description, and a footer row with the "Out of Stock"
badge (when `stock === 0`) or nothing (when in stock) opposite the price.

**Catalog page** (`/products`): mirrors `app/services/page.tsx` exactly — category-grouped sections
(`groupServicesByCategory` pattern reused as `groupProductsByCategory`), `grid sm:grid-cols-2
lg:grid-cols-3 gap-6` per category group, `SectionHeading` at the top, empty-state fallback box when
zero products.

**Product detail page** (`/products/[slug]`): mirrors `app/services/[slug]/page.tsx`'s two-column
`grid lg:grid-cols-[1fr_320px] gap-8` layout — main `<article>` with category eyebrow, `h1`, image (if
present), long description; sticky `<aside>` with a `dl` for Price and Stock (`"In Stock"` in
`text-gray-400` or the "Out of Stock" badge in place of a value row). No CTA button in the aside this
phase (see Copywriting — no purchase action exists yet).

**Recommended Products section** (on `/services/[slug]`, new): inserted below the existing
`longDescription` paragraph inside the same `<article>` or as a new full-width section beneath the
two-column grid (implementer's choice, whichever reads cleaner against the existing DOM) — reuses
`SectionHeading` and the same `ProductCard` grid (`grid sm:grid-cols-2 lg:grid-cols-3 gap-6`) as the
`/products` catalog page, so a product recommended in two places always looks identical.
