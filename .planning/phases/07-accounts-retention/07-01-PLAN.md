<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Auth API | Untrusted email/password JSON on register/login |
| Auth API → Identity store | Trusted UserManager hash + AspNet* tables (shared with staff) |
| Browser localStorage → Account UI | JWT bearer; XSS can exfiltrate within token lifetime |
| Landing client key vs dashboard staff key | Separate storage namespaces prevent accidental cross-app session reuse |

## STRIDE Threat Register (ASVS L1)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Spoofing | AuthController.Login/Register | high | mitigate | Identity password hasher via UserManager; login keeps uniform Invalid email or password 401 (no user enumeration); register uses FluentValidation + Identity errors as ValidationProblem |
| T-07-02 | Tampering | JWT claims / Role | high | mitigate | Server mints roles via JwtTokenService from GetRolesAsync only; AddToRoleAsync(Client) only on register — clients cannot self-assign Staff/Owner |
| T-07-03 | Information Disclosure | Register duplicate email | medium | mitigate | Return ValidationProblem without confirming alternate accounts beyond Identity descriptions; login remains uniform 401 (ASVS L1 acceptable; rate-limit deferred Phase 8) |
| T-07-04 | Elevation of Privilege | Client role APIs (later) | high | mitigate | This plan seeds Client and returns Client JWT only; account history endpoints in 07-02 use [Authorize(Roles=Client)] — do not authorize Staff tokens for client account routes on landing |
| T-07-05 | Information Disclosure | localStorage JWT XSS | medium | accept | Same Phase 3 tradeoff (D-02): workday JWT lifetime bounds exfil; CSP polish Phase 8; separate zhs.client.auth key reduces staff-session blast radius |
| T-07-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new packages this plan — reuse Identity/JWT/FluentValidation/Next in-repo (RESEARCH Package Legitimacy N/A) |
</threat_model>
