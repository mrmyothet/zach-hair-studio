# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope: `landing-page/` only (ACCT-01..07) — client register/login on `/account/*`, an authenticated
account shell with **Bookings | Orders** tabs and date-desc history, self-service cancel/reschedule
for upcoming appointments, loyalty balance display + redeem-at-checkout, and Navbar Account vs
Login/Register entry. Extends the **already-established** hand-rolled Tailwind design system from
Phases 1–6 — no design system reset, no new dependency, no shadcn. Guest checkout from Phase 6
remains valid; accounts are additive. Server ownership only (ACCT-06) — the UI never trusts or
displays another client's records.

**Price / points formatting**:

- Money: reuse `Intl.NumberFormat("en-US", { style: "currency", currency: "USD", maximumFractionDigits: 0 })` (catalog/cart).
- Loyalty: integer points with locale grouping (`Intl.NumberFormat("en-US")`); redeem preview shows `$5` off per 10 pts as server-returned discount cents formatted via the same price formatter — never invent discount $ client-side (D-15).

**Auth session (UI contract)**: JWT in `localStorage` mirroring `dashboard/lib/auth.ts` (D-02) under a **client-scoped** key (e.g. `zhs.client.auth`) — never share the staff `zhs.staff.auth` key. Attach `Authorization: Bearer` on account/history/loyalty/checkout-redeem calls. On 401: clear session and redirect to `/account/login`.

## Spacing Scale

Declared values (multiples of 4), identical to Phase 6:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, tab underline thickness, badge padding |
| sm | 8px | Label-to-input `mb-2`, chip internal `gap-2`, loyalty redeem stepper gaps |
| md | 16px | Default form-field spacing, history-row internal gaps, tab list `gap-4` |
| lg | 24px | Card padding (`p-6`/`p-7`), claim-confirm panel spacing |

| 2xl | 48px | Between auth form and secondary links; loyalty strip above history |
| 3xl | 64px | Page section vertical padding (`py-16`) |

Exceptions (baseline-inherited; stay consistent):

- **44px minimum touch target** (`h-11` / `min-h-11`) for tabs, Cancel/Reschedule actions, slot chips, redeem +/- steppers, navbar Account/Login links.
- **128px top padding** (`pt-32`) on every new `<main>` under `/account/*` and on checkout when loyalty UI is added — fixed Navbar clearance.
- **`py-2.5` (10px)** on Bookings|Orders tab pills and Phase 2–style chips — registered pre-existing exception.
- Auth forms use `max-w-md mx-auto`; account shell uses `max-w-5xl mx-auto px-6` (matches cart/checkout content width).

## Typography

Four sizes, two weights for every *new* component — Phase 6 discipline:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px (`text-xs`) | Regular (400) | 1.4 — uppercase `tracking-wider`; form labels, tab labels, status chips, loyalty "pts" micro-copy, navbar Account/Login |
| Body | 14px (`text-sm`) | Regular (400) | 1.5 — form helpers, history metadata, empty/error body, redeem helper, claim-confirm body |
| Heading | 20px (`text-xl`) | Semibold (600) | 1.2–1.3 — section titles inside account shell, history row titles (service/product name), empty-state headings, modal titles |
| Display | 36 / 48px (`text-4xl md:text-5xl` via `SectionHeading` or auth `h1`) | Regular (400), `font-serif` | 1.15 |

Weight notes:

- **Regular (400)** default for body, labels, serif Display.
- **Semibold (600)** for primary CTAs, history row titles, tab selected state, loyalty balance number emphasis, empty-state headings.
- **`font-bold` (700) on price / discount values only** — baseline-inherited from catalog (`text-gold font-bold`); loyalty discount line uses the same treatment. Do not add a third general weight.

## Visual Anchor (focal point)

Each primary screen leads the eye to exactly one gold-accented element:

- `/account/login` · `/account/register` — gold primary submit (**Log In** / **Create Account**).
- `/account` (shell) — selected **Bookings|Orders** tab underline/border in gold; loyalty balance number in gold when present.
- Booking detail / upcoming row — gold **Reschedule** primary; Cancel stays quiet destructive (see Color).
- `/checkout` (logged-in redeem) — gold **Apply Points** / updated Total; Continueto Payment remains the page CTA.
- Navbar — gold `PersonIcon` on Account when authenticated; Login/Register text link matches Cart treatment (icon gold, label gray→gold hover).

Nothing else on a screen may compete for the gold accent.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#181410` (`bg-charcoal`) | Page background behind account/auth screens |
| Secondary (30%) | `#241c15` (`bg-charcoal-light`) | Auth form card, history rows, loyalty strip, claim panel, tab panels — `border border-white/5 rounded-2xl` |
| Accent (10%) | `#d4af6a` | See "Accent reserved for" |
| Destructive | `rose-400` text on `rose-500/10` bg + `rose-500/20` border | Error banners **and** Cancel confirmation primary action only |

**Accent reserved for** (nothing else may use gold):

1. Navbar **Account / Login** entry (`PersonIcon` `text-gold`) alongside existing Cart gold affordance
2. **Primary CTAs**: Create Account, Log In, Reschedule (confirm), Apply Points, Book Now (existing), Continue to Payment (existing) — `bg-gold hover:bg-gold-dark text-charcoal font-semibold rounded-full`
3. **Selected tab** Bookings|Orders — `border-gold text-gold` (unselected: `border-white/10 text-gray-300`)
4. **Loyalty balance** integer + "pts" and redeem discount $ line (`text-gold font-bold`)
5. **Focus/active borders** on auth and redeem inputs (`focus:border-gold`, Phase 2 `inputClass`)
6. Gold eyebrow labels via `SectionHeading`
7. Status chip for **Upcoming / Confirmed** only when needing positive emphasis (`border-gold/40 text-gold bg-gold/10`) — Completed/Cancelled stay neutral gray

Never use gold for: body text, Cancel (pre-confirm), Log out, disabled states, error text, past/cancelled row chrome, or decorative fills outside this list.

**Destructive reserved for**:

- Cancel appointment confirmation dialog primary button and error banners only.
- Cancel is **not** a quiet gray link (unlike cart Remove) — it releases a real slot (D-09); requires confirmation.

## Additional Notes — Component Patterns

**Navbar Account entry (D-07).** Extend shared `Navbar` (`"use client"`). Desktop: place **Log In** or **Account** to the left of Cart (left of Book Now), same classes as Cart link (`inline-flex items-center gap-2 text-gray-300 hover:text-gold … uppercase`). Use `PersonIcon` `w-5 h-5 text-gold`. Mobile: menu row above Cart. Session from client auth helper; missing/expired JWT → Log In.

**Auth pages** (`/account/login`, `/account/register`). Centered card `bg-charcoal border border-white/5 rounded-3xl p-7 md:p-10 max-w-md mx-auto` under `SectionHeading`. Fields use Phase 2 `inputClass`. Full-width gold submit. Secondary text link between login ↔ register. After successful login/register → `/account` (or claim panel first when D-04 matches).

**Account shell** (`/account`, `/account/bookings`, `/account/orders`). `pt-32` main → `SectionHeading` → loyalty strip → tab list → panel. Tabs: `flex gap-3` chips `rounded-full border px-5 py-2.5 text-sm min-h-11` (selected gold). Unauthenticated visit to `/account*` → redirect `/account/login`.

**Loyalty strip.** `bg-charcoal-light border border-white/5 rounded-2xl px-5 py-4 flex flex-wrap items-center justify-between gap-4` — label + gold `{n} pts` + helper. No tier UI (RETN-02 deferred).

**History rows.** Same card anatomy as cart lines: `bg-charcoal-light border border-white/5 rounded-2xl p-5 md:p-7`. Bookings: left meta stack, right actions. Orders: number, date, total gold. Detail may be expand-in-place or `/account/bookings/[id]` — if routed, ownership 404 uses Not Found copy above.

**Cancel UX (D-09, D-11).** Upcoming Confirmed only, until start. Confirm panel required. Success updates list without full-page navigation preferred.

**Reschedule UX (D-10).** Single flow: pick new slot (Phase 2 chips) → **Confirm New Time** → server cancel-and-rebook transaction. On 409 slot taken: Phase 2 recovery copy ("That time was just taken…") + refresh slots. Do not leave orphan cancelled-without-new unless user abandons (abandon = no mutation).

**Checkout redeem (D-15, D-16).** When JWT present on `/checkout`, insert loyalty block above Continue to Payment / in Order Summary: balance, multiples-of-10 control, Apply Points. Totals must reflect **server-recomputed** discount. Never trust client `$` off. Guest path: no loyalty block.

**IDOR-safe UI (ACCT-06 / D-08).**

- Do not accept `clientId` / `userId` query params for scoping lists.
- Detail fetches use route id + bearer only; ignore any owner id in the body.
- Error and empty states must not leak existence of other users' records (generic Not Found).
- Never render email/phone/name from a response that failed ownership.
