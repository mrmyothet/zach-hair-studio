## Phase Goal

**As a** client, **I want to** pick a service and book a real open slot with my chosen stylist, **so that** my appointment is confirmed and never double-booked.

> Vertical slice: the public UI. This is where the whole phase becomes a thing a real person can do on the site — walk the progressive-reveal /book flow, see real open times in salon-local time, confirm, and get an on-screen confirmation (plus a best-effort email). It also removes the last traces of the retired free-text booking path from the frontend (D-14).

<objective>
Build the client data layer (lib/appointments.ts) and the /book progressive-reveal booking UI per the UI-SPEC and D-15, wire it into the existing RSC page (preserving the ?service deep link), and retire the legacy frontend booking path — delete BookingRequestForm, repoint the homepage Contact form into the /book flow, and remove the dead createBooking client.

Purpose: Deliver BOOK-02 (book end-to-end on the public site), the on-screen half of BOOK-03 (D-11 self-sufficient confirmation), and the stylist picker of BOOK-06, while honoring D-14's wholesale retirement on the frontend.
Output: A working /book page, an appointments API client, a repointed homepage, and no remaining calls to /api/bookings.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → API | Client fetches slots and posts a guest booking; server is authoritative (client never computes slot validity) |
| rendering | DateTimeOffset from the API is rendered with the salon zone, not the browser zone (correctness boundary) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-11 | Spoofing/Tampering | Client-side slot validity | medium | mitigate | UI treats the server as authoritative; a stale slot yields a 409 handled by the recovery UX, and the server re-validates + the unique index backstops it |
| T-02-12 | Information Disclosure | Zod parse of API responses | low | mitigate | Response schemas (D-18) reject malformed payloads before render; createAppointment surfaces status without leaking internals |
| T-02-05 | Tampering | Browser-timezone misrender | medium | mitigate | Times rendered from the DateTimeOffset offset + salon zone label, never the browser zone (D-16) |
| T-02-SC | Tampering | npm installs | low | accept | No new npm packages (Zod/next already present); no install step |
</threat_model>
