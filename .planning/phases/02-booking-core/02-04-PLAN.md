## Phase Goal

**As a** client, **I want to** pick a service and book a real open slot with my chosen stylist, **so that** my appointment is confirmed and never double-booked.

> Vertical slice: the write side and the heart of the phase. After this plan a client (via the API) can confirm a booking that the database guarantees is not double-booked, gets a best-effort email, and — crucially — the two hardest correctness proofs (SC4 concurrency, SC5 DST round-trip) are green against real SQL Server. BOOK-02/03/04 and the assignment half of BOOK-06.

<objective>
Implement AppointmentsService with the candidate-stylist try-insert retry loop (no manual transaction), the create DTO + validator + response DTO + mapper, the Resend best-effort email service, and the POST /api/appointments endpoint that maps success→201, validation→400, and unique-index conflict→409. Prove it: validator tests, Any-stylist assignment, and — on the real SQL Server fixture — the two-concurrent-requests SC4 test and the DST round-trip SC5 test.

Purpose: Deliver the double-booking-safe booking (SC4/BOOK-04), the end-to-end booking write (BOOK-02), the best-effort confirmation email (BOOK-03/D-11), and deterministic Any-stylist assignment (BOOK-06/D-07).
Output: AppointmentsService + ResendEmailService + POST endpoint + the SC4 and SC5 tests, all green.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → API (POST /api/appointments) | Untrusted guest input: serviceId, stylistId, StartsAt, name/email/phone |
| API → SQL Server | Multi-row insert whose atomicity + uniqueness the DB enforces |
| API → Resend (external) | Outbound HTTP with a secret bearer token; client strings flow into the email body |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | Slot booking race (TOCTOU) | critical | mitigate | Retry loop relies on the Plan-01 unfiltered unique index; SC4 concurrency test proves exactly one 201/one 409; no app-level-only check |
| T-02-07 | Information Disclosure | Unhandled SqlException in a 500 | high | mitigate | Catch DbUpdateException(2601/2627) → ProblemDetails 409 in ALL environments; no SQL detail leaks (V7) |
| T-02-08 | Tampering | Email HTML/header injection via client name/email | medium | mitigate | FluentValidation bounds + WebUtility.HtmlEncode on interpolated client fields before building the html body |
| T-02-03 | Information Disclosure | RESEND_API_KEY | high | mitigate | Read from Resend:ApiKey (user-secrets/env, D-13); never appsettings; gitleaks enforced |
| T-02-09 | Tampering | Client-echoed slot trusted as bookable | high | mitigate | Server re-validates StartsAt against SlotService before insert; the unique index is the final backstop |
| T-02-10 | Denial of Service | Unauthenticated/unthrottled POST | low | accept | Rate limiting is Phase 8 (LAUNCH-05); documented as by-design for this phase |
| T-02-SC | Tampering | NuGet installs | low | accept | No new packages (HttpClient is BCL); no install step in this plan |
