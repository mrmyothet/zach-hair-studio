## Spacing Scale

Declared values (multiples of 4), inherited from Phases 6–7 — do not invent a new scale:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, badge padding |
| sm | 8px | Compact gaps, label-to-input |
| md | 16px | Default element spacing; content `px-4` floors |
| lg | 24px | Card padding (`p-6`), section internal gaps (`px-6`) |
| xl | 32px | Layout content gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page section vertical padding (`py-16`) |

Exceptions (baseline-inherited; polish must preserve or restore):

- **44px minimum touch target** (`min-h-11` / `min-w-11` / `h-11`) on every interactive control: nav links, hamburger, CTAs, tab chips, slot chips, schedule toolbar buttons, form submits, dialog actions, cart/account affordances.
- **128px top padding** (`pt-32`) on landing `<main>` routes under fixed Navbar — do not shrink below this when fixing polish.
- **`py-2.5` (10px)** on pre-existing chip/tab anatomy — registered exception; do not “normalize” to 8/12 if it breaks chip height below 44px combined with padding.
- Content gutters: landing `max-w-7xl|5xl mx-auto px-6`; dashboard `px-4 md:px-6`.

## Responsive Polish Checklist (LAUNCH-01)

Verification is checklist + brief human spot-check (CONTEXT). Automated Playwright-only gate is deferred.

### Breakpoints (must pass)

| Viewport | Width | Apps |
|----------|-------|------|
| Mobile | 375px | landing-page + dashboard |
| Mobile large | 390–430px | landing-page + dashboard |
| Tablet | 768px | landing-page + dashboard |
| Desktop | 1280px | landing-page + dashboard |
| Wide | 1440px+ | landing-page (hero/nav); dashboard schedule grid |

### Pass criteria (all must be TRUE)

1. **No horizontal page overflow** — `document` / body does not scroll horizontally at any listed breakpoint (intentional inner `overflow-x-auto` on WeekChips / WeekStripEditor / DayGrid is allowed **inside** a contained region, not the page).
2. **Touch targets ≥ 44×44px** for every primary interactive control (links, buttons, icon-only controls, hamburger, tabs, chips used as buttons). Decorative non-hit icons exempt.
3. **Fixed Navbar clearance** — landing content under the fixed nav is not obscured (`pt-32` or equivalent retained).
4. **Mobile nav** — landing hamburger menu stacks Account/Login, Cart, Book Now without clipping; closes on navigate; targets ≥44px.
5. **Forms** — auth, book, checkout, service form fields remain full-width within gutters; no truncated labels; submit buttons remain fully visible above fold or after normal vertical scroll (not clipped by overflow:hidden parents).
6. **Dashboard schedule** — Day/Week views usable on phone (scroll contained); toolbar wraps (`flex-wrap`) without overlapping wordmark; detail panel is full-width sheet on mobile (`w-full`), `md:max-w-md` drawer on desktop.
7. **Images / media** — gallery/hero/product images scale within container (`max-w-full` / object-fit as already used); no intrinsic width blowout.
8. **Long text** — service names, client names, product titles wrap or `line-clamp-*` as already specified; no unbroken string forces page-wide overflow.
9. **No visual regressions** — tokens, radii, and gold accent reserved-list unchanged; no new card shells in hero; no purple theme drift.

### Priority audit surfaces (Claude's discretion after scan)

**Landing:** Navbar, Hero, Services, booking form / slot grid, products/cart/checkout, account shell tabs, ClaimHistoryPanel, Footer, ChatWidget.

**Dashboard:** DashboardNav, ScheduleToolbar + DayGrid/WeekChips, AppointmentDetailPanel, ServiceForm, WeekStripEditor / TimeOffCalendar, login.

### Out of scope for UI polish

- Full visual redesign / rebrand (CONTEXT deferred)
- New landing sections or promotional strips
- Changing dashboard light theme to dark (or vice versa)
- Replacing hand-rolled components with shadcn
- Playwright-only acceptance (human spot-check remains)

## Additional Notes — Polish Execution Guidance

1. **Audit first, then fix.** Prefer minimal class changes (`min-h-11`, `min-w-0`, `overflow-x-hidden` on a specific wrapper, `flex-wrap`, `truncate`/`line-clamp`) over structural rewrites.
2. **Dual app tokens.** Never copy landing `bg-charcoal` into dashboard or dashboard `bg-surface` into landing.
3. **Contained scroll vs page scroll.** If a schedule grid needs horizontal pan, keep it on the grid container with a visible edge fade or padding — never on `body`.
4. **Chat widgets.** Ensure floating ChatWidget / AdminChatWidget do not cover primary CTAs on 375px; nudge `bottom`/`right` or shrink hit area only if they fail the checklist — no redesign of the widget chrome.
5. **Verification artifact.** Record breakpoint pass/fail in Phase 8 VERIFICATION.md; human spot-check mobile + desktop is required (CONTEXT).
