<objective>
Close gap G-04-5: adding a time-off range on the dashboard's Availability page throws React's "Cannot update a component (`AvailabilityPage`) while rendering a different component (`WeekStripEditor`)" error, which blocked UAT test 11 and halted the rest of the Phase 4 user-flow run.

The root cause is already diagnosed and confirmed in `.planning/debug/G-04-5-weekstrip-render-setstate.md` - do NOT re-diagnose it. `WeekStripEditor.handleUp()` calls `emitChange()` -> `onChange()` from inside the functional updater passed to the previewRange setter. React invokes that updater during WeekStripEditor's render phase, so the reach-into-parent setState fires while WeekStripEditor is the currentlyRenderingFiber. The error surfaces at test 11 rather than test 10 because the queued updater is only flushed on the next render, which the time-off click triggers.

Purpose: restore the phase's user story - staff keep stylist availability accurate from the dashboard - without a console-error wall in the middle of the flow.
Output: a WeekStripEditor whose drag commit runs in the pointerup handler with pure state updates, plus a lint guard that makes this bug class fail at `npm run lint` rather than at UAT.
</objective>
