<objective>
Close gap G-04-6: the Availability page's week strip (`WeekStripEditor.tsx`) lets staff paint brand-new working-hours blocks by dragging on empty track, but has no way to shrink an already-painted segment. Every drag on the track routes through `mergeSegments()`, which is additive-only (`last.end = Math.max(last.end, seg.end)`), and the only way to reduce a segment today is to delete it outright via the x button and repaint smaller from scratch. This is a pre-existing interaction-design gap from the component's original 04-04 implementation (confirmed by the diagnosed debug session at `.planning/debug/week-strip-shrink-not-possible.md`), not a regression from 04-06 -- do NOT re-diagnose it.

This plan adds a genuine edge-resize interaction: a small, hover-revealed resize-handle strip at each segment's left and right edge, with an ew-resize cursor. Grabbing a handle and dragging enters a resize mode scoped to that one segment's boundary -- clamped against its own opposite edge and any adjacent segment on the same day -- and commits by directly replacing that segment's start or end value, bypassing `mergeSegments` entirely so the shrink cannot be silently re-expanded.

Purpose: restore the phase's user story -- staff keep stylist availability accurate from the dashboard -- for the one gesture (shrink) it never supported, closing UAT Test 13's blocking issue (04-05's conflict hard-block cannot be exercised by shrinking hours if the UI has no way to shrink them).
Output: `WeekStripEditor.tsx` gains a resize-handle affordance and a ref-committed edge-resize drag mode, alongside the unchanged paint-new-segment and remove-segment gestures.
</objective>
