# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope: two new `dashboard/` surfaces — **Services** (MGMT-01, Owner-only CRUD + soft-retire + image
upload) and **Availability** (MGMT-02/MGMT-03, all-staff working-hours + time-off editor with a
hard-blocking conflict check) — plus a shared nav addition so staff can reach both from anywhere in
the dashboard (D-16). This phase does **not** introduce a new design system: it extends the exact
`dashboard/` visual language Phase 3 already shipped and locked in `03-UI-SPEC.md`. Every token,
type role, and component pattern below is inherited verbatim from Phase 3 unless a row is explicitly
marked **new (Phase 4)**.

## Spacing Scale

Declared values (must be multiples of 4) — unchanged from Phase 3:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, chip/badge inline padding, calendar-cell gutter |
| sm | 8px | Compact spacing — label-to-input, list-row action-icon gaps |
| md | 16px | Default panel/card padding, form field vertical rhythm |
| lg | 24px | Section padding, gap between page header and content |
| xl | 32px | Layout gaps — gap between Services list and its Add button row |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Not used at dashboard density (unchanged) |

Exceptions (inherited, still apply): **44px minimum touch target** on every icon button, toggle, and
form control (WCAG 2.5.5) — Edit/Retire/Reactivate row actions, calendar day cells' tap area, week-strip
segment handles.

**New (Phase 4) spacing exceptions:**

- **Week-strip row height = 40px** (`h-10`, a 4px-multiple), one row per weekday (Mon–Sun), matching
  the existing 20px-per-15-min proportional-sizing precedent from the day grid but at a coarser,
  "compact" grain appropriate to a weekly editor, not a daily one.
- **Week-strip hour width = 24px per hour** (`w-6`, a 4px-multiple) against a default business window
  of **06:00–22:00** (16 hours → 384px total bar width on desktop; horizontally scrollable under
  768px). The 06:00–22:00 window is a **default, not a locked salon-hours fact** — no upstream
  artifact specifies actual salon opening hours, so this is flagged for the executor to confirm
  against seed data or make configurable.
- **Segment drag/paint snaps to 15-minute increments**, reusing Phase 2's existing 15-minute slot
  grid (BOOK-01) so a stylist's painted hours always align to the same grid the public booking flow
  reads slots from.
- **Time-off calendar day cells = 40px × 40px** (`h-10 w-10`, 4px-multiples) with 4px gutter, standard
  7-column month grid, matching the week-strip's 40px row rhythm for visual consistency between the
  two paired editors.

## Color

Unchanged dominant/secondary/accent tokens from Phase 3:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#faf8f4` (`bg-surface`) | Page background behind both new pages' content |
| Secondary (30%) | `#efe9df` (`bg-surface-alt`) | Card/panel surfaces (service form, availability editor panels, conflict panel), list-row zebra striping, header bar |
| Accent (10%) | `#a87f3d` (`text-gold-dark` / `bg-gold-dark`) | See "Accent reserved for" below — extends Phase 3's list, does not replace it |
| Destructive | `#e11d48` (`text-rose-600` / `bg-rose-600`) | Retire-service confirmation, conflict-blocked save banner, validation error text/banners |

**Accent reserved for** (Phase 3's 7-item list still applies verbatim; Phase 4 adds items 8–13 —
nothing outside this combined list may use gold):

1–7. *(unchanged — see `03-UI-SPEC.md`: Log In button, Add Staff Member button, Confirmed-appointment
left border, Completed checkmark badge, active Day/Week toggle + Today button, selected date in date
picker, focus rings)*

8. **"Add Service" / "Save Service" primary submit buttons** on the Services form — same treatment as
   item 2 ("Add Staff Member")
9. **"Save Changes" primary submit button** on the Availability page (the single combined save for
   both hours and time-off edits — see Component Patterns)
10. **Painted working-hours segments** on the week-strip (`bg-gold-dark/15 border border-gold-dark`) —
    represents "the salon is open," the direct weekly analog of item 3's Confirmed-appointment gold
    border
11. **The currently-selected stylist** in the stylist picker (Availability page)
12. **The active nav link** in the dashboard header (new — see Component Patterns: `DashboardNav`)
13. **Focus ring on the week-strip drag handles and calendar day cells**, same `focus:border-gold-dark`
    pattern as item 7, extended to the two new interactive-control surfaces

Never use gold for: body text, disabled states, the "Add Time Off" secondary button (kept neutral —
see Component Patterns), time-off painted ranges (explicitly **not** gold; time off is "unavailable,"
not "open" — see below), or any decorative fill outside the 13-item list above.

**Time-off painted ranges (new derived treatment, not a new color token):** `bg-muted/15
border-2 border-dashed border-muted`, `text-ink` for the optional reason label. Deliberately neither
gold (not "available") nor destructive-red (time off is routine, not an error/danger state) — reuses
the existing muted token the same way Phase 3 used it for Cancelled/No-show block backgrounds.

**Status chip color-coding for the Services list** (mirrors Phase 3's Confirmed/Cancelled pattern):

| Status | Chip treatment |
|--------|------------------|
| Active | no chip shown — the unmarked default state (consistent with "never use gold for... the default/inactive case"; Active needs no visual flag since it's the common case) |
| Retired | `bg-surface-alt/60` (muted), `text-muted` "Retired" label, row content at full opacity but the row itself gets a subtle muted left border (`border-l-4 border-border`, same neutral-gray treatment Phase 3 used for Cancelled appointments) — never red, since retiring is reversible and routine, not an error |

> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 17 covered, 1 backstop, 1 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Services list (list-collection) | ✅ covered | Zero services renders the Copywriting Contract's "No Services Yet" heading below the Add Service CTA — only reachable pre-seed, not a normal runtime path. |
| error | Services list (list-collection) | ✅ covered | Load failure renders "Couldn't Load Services." + Refresh, same shape as Phase 3's schedule error state. |

## Component Patterns

Prescriptive shapes for the pieces this phase introduces, so the planner/executor don't have to
invent visual structure mid-implementation.

**`DashboardNav` (new, shared across all dashboard pages):** each existing page currently hand-rolls
its own `<header>` (see `dashboard/app/schedule/page.tsx`'s header block). Rather than let a third and
fourth page duplicate that markup, extend the existing header pattern with a left-of-center nav-link
row between the wordmark and the right-side session/actions cluster: **Schedule · Services ·
Availability**. Services is omitted entirely from the DOM for Staff-role sessions (D-16 "hide," not
disable). The active page's link uses `text-gold-dark font-semibold`; inactive links use `text-ink
hover:text-gold-dark`. This is a refactor of the *existing* header markup into one shared piece, not a
new layout system — same `bg-surface-alt border-b border-border` bar, same right-side "Add staff" /
session name / logout cluster unchanged.

**Services page (`/services`, Owner-only, MGMT-01):** page heading "Services" + primary "Add Service"
button (top-right, gold-dark). Below: a list/table (`bg-surface-alt` rows on `bg-surface` page,
`border-b border-border` row dividers) with columns Name, Category, Duration, Price, Status,
Actions. Clicking a row or its Edit action opens the same `ServiceForm` used for creation, pre-filled
— a single form component in two modes (create/edit), not two separate components, mirroring the
Add Staff page's single-form precedent. Retire uses the existing `ConfirmDialog` component with new
`CONFIRM_COPY.Retired` copy (destructive-red styling, since it removes public bookability even though
it is reversible). Reactivate is a single inline button with no dialog (D-15 discretion: immediate,
reversible, low-stakes).

**`ServiceForm`:** vertical form in a `bg-surface-alt rounded-2xl p-8 border border-border` card,
identical shell to the Add Staff card. Fields in order: Name, Short description, Long description
(textarea), Category, Duration (minutes, number input), Price (currency input), Image
(`ImageUploadField`), then the primary Save button. Uses the same `inputClass`/`Field` wrapper already
defined in `dashboard/app/staff/new/page.tsx` — do not redefine a second input style.

**`ImageUploadField`:** a 160px×160px (4px-multiple) dashed-border box (`border-2 border-dashed
border-border rounded-xl`). Empty: centered "No image yet" caption + Upload Image button. Populated:
thumbnail fills the box, with Replace/Remove controls below it. Uploading: spinner overlay, box
interaction disabled. Accepts `image/jpeg`, `image/png`, `image/webp`, max 5MB (default limits — not
specified upstream, flagged as the executor's confirmed baseline unless product decisions override).

**Availability page (`/availability`, all staff, MGMT-02/MGMT-03):** page heading "Availability" +
`StylistPicker` (a horizontal row of stylist name chips, or a select on narrow viewports — selected
chip gets the gold-dark treatment per accent item 11). Below the picker, two paired sections stacked
vertically: **Weekly Hours** (`WeekStripEditor`) then **Time Off** (`TimeOffCalendar`), each in its own
`bg-surface-alt rounded-2xl p-6 border border-border` card. A single **Save Changes** button (gold-dark,
accent item 9) sits below both sections and submits both hours and time-off edits together in one
API call — not two separate saves — so the conflict check (D-12: runs on both shrinking hours and
adding time off) has one authoritative moment to evaluate the whole new state.

**`WeekStripEditor`:** 7 horizontal rows (Mon–Sun, Label-role weekday abbreviation on the left), each
row a 40px-tall, 24px/hour bar spanning the default 06:00–22:00 window (see Spacing Scale). Staff
click-drag across the bar to paint a working-hours segment (`bg-gold-dark/15 border border-gold-dark`,
snapping to 15-minute increments); dragging again elsewhere on the same row paints an additional
non-contiguous segment (the D-06 gap-as-break mechanic — a gap between two segments is the "lunch
break," with no separate Break entity). Hovering a painted segment reveals a small remove ("x")
control at its edge; clicking removes just that segment. A weekday with no segments shows the "Closed"
muted overlay. Each segment maps 1:1 to a `StylistWorkingHours` row for that `DayOfWeek`.

**`TimeOffCalendar`:** a standard single-month 7-column grid (`ChevronLeftIcon`/`ChevronRightIcon` for
month navigation, Label-role weekday headers, 40px×40px day cells). Staff click a start date then an
end date (or drag across a range) to paint a `StylistTimeOff` block — rendered as the dashed-muted
band described in the Color section, spanning the painted date cells, with an optional reason input
appearing once a range is painted. A Remove control appears on hover/tap of an existing range. Below
the calendar: "No time off scheduled." caption when empty (per Copywriting Contract).

**`ConflictList` / conflict panel:** rendered inline below the Save Changes button (not a modal — D-11
wants an actionable-in-place list, not a dead end that leaves the page). On a hard-blocked save
response, the panel appears with `border-2 border-rose-600 bg-rose-600/5 rounded-xl p-4`, the
Copywriting Contract's heading/body, and one row per conflicting appointment (client, service, stylist,
salon-local time — matching Phase 3's existing salon-local time formatting from the schedule/detail
panel). Rows scroll internally past ~6 (see UI Considerations). Save Changes stays enabled after a
block so staff can retry once conflicts are resolved elsewhere (no forced page reload).

## Open Questions

Carried forward for the planner/executor to resolve or flag to the owner — not blocking this spec:

1. **Default business-hours window (06:00–22:00) for the week-strip.** No upstream artifact states the
   salon's actual operating hours; this spec picked a plausible default purely for layout math. Confirm
   against Phase 2 seed data or make the window itself editable if the salon's real hours differ.
2. **Image storage backend** (local `wwwroot`/static folder vs. blob storage) is explicitly Claude's
   Discretion per `04-CONTEXT.md`. This spec assumes local static-folder storage for dev-simplicity
   consistency with the project's "LocalDB + next dev + dotnet run is enough" constraint, but does not
   lock the backend choice — that's a planning/architecture decision, not a visual one.
3. **Exact week-strip drag mechanic** (click-drag paint vs. click-then-click range select) — this spec
   recommends click-drag with 15-minute snapping as the more direct/discoverable interaction, but
   CONTEXT.md leaves the final mechanic to the executor.
4. **Conflict API response shape** (400 vs. 409 ProblemDetails) is Claude's Discretion per CONTEXT.md;
   this spec only prescribes the panel's visual/copy contract once a conflict payload arrives, not the
   HTTP status it arrives on.
5. **Retired-services visibility on the list** — this spec recommends "Retired rows shown after Active
   rows, or behind a toggle" but does not lock which; either satisfies the populated-state resolution
   above.
