# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope: the new `dashboard/` Next.js app — staff login (DASH-05), the day/week schedule view
(DASH-01), the appointment detail view (DASH-02), status-update quick actions and confirmation
dialogs (DASH-03/DASH-04), and the Owner-only "add staff user" screen (D-04). This is a **brand-new
app**, not an extension of `landing-page/` — per D-15 it deliberately reuses the salon's fonts and
accent color for brand familiarity, but runs on **light neutral surfaces** in a dense, tool-like
layout, not `landing-page/`'s dark charcoal marketing theme. Where this spec's color values diverge
from `landing-page/app/globals.css`, that divergence is D-15, not drift.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside chips/badges, table cell inline padding |
| sm | 8px | Compact spacing — label-to-input, toolbar button internal padding, quick-action icon gaps on a block |
| md | 16px | Default panel/card padding, gap between toolbar controls, detail-panel row spacing |
| lg | 24px | Section padding, gap between the day-grid and its toolbar, modal/detail-panel outer padding |
| xl | 32px | Layout gaps — gap between the week-view's 7 day columns' outer margin, login-card vertical centering offset |
| 2xl | 48px | Major section breaks — space above/below the schedule toolbar on desktop |
| 3xl | 64px | Not used at dashboard density; reserved if a future marketing-style page is added (none this phase) |

Exceptions:

- **44px minimum touch target** (`min-h-11`/`min-w-11`) for every quick-action icon button on an
  appointment block, toolbar icon button (prev/next/today/refresh), and the Day/Week toggle segment —
  same accessibility floor already used in `landing-page/components/AppointmentBookingForm.tsx`'s
  slot-grid buttons (WCAG 2.5.5).
- **Time-grid row height = 20px per 15 minutes** (a 4px-multiple: `20 = 4 × 5`). A 30-minute
  appointment renders an 80px-tall block (30 min × 2 rows × 20px... i.e. 2 × 20px = 40px minimum
  proportional height); concretely: block height in px = `(durationMinutes / 15) × 20`. A 60-minute
  appointment is 80px tall, a 90-minute appointment is 120px tall. This keeps block sizing
  proportional to duration (D-05) while staying on the 4px grid.
- Appointment blocks shorter than **40px** (i.e. ≤30-minute services) collapse their quick-action
  icons into a single "⋯" overflow icon button (still 44px tap target) rather than showing three
  full-size icon buttons that would overflow the block — flagged for the planner/executor, not a
  locked pixel rule.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px (`text-xs`) | Regular (400) | 1.4 — uppercase, `tracking-wider`: stylist column headers, time-axis labels, form field labels, status tags ("Completed", "Cancelled", "No-show") |
| Body | 14px (`text-sm`) | Regular (400) | 1.5 — appointment block text (client name, time, service), table/list rows, form inputs, toolbar button labels, detail-panel field values |
| Heading | 18px (`text-lg`) | Semibold (600) | 1.3 — panel/section titles ("Today's Schedule", detail-panel title, "Add Staff Member", modal titles) |
| Display | 24px (`text-2xl`), `font-serif` | Semibold (600) | 1.2 — page-level title only: the dashboard's top-bar wordmark ("Zach Hair Studio" or "Schedule") and the login page's brand heading |

Weight notes:

- **Regular (400)** is the default for body copy, labels, and all appointment-block/table content.
- **Semibold (600)** is reserved for panel/section headings, the Display role, the primary CTA button
  label, and the currently-active toolbar segment (e.g. the selected Day/Week toggle text).
- Exactly 4 sizes / 2 weights, denser than `landing-page/02-UI-SPEC.md`'s marketing-scale sizes —
  intentional per D-15's "clean, dense, tool-like layout."

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#faf8f4` (`bg-surface`) | Page background behind the toolbar and schedule grid; login page background |
| Secondary (30%) | `#efe9df` (`bg-surface-alt`) | Appointment-block card surface (Confirmed/Completed state), detail-panel/modal background, sidebar/nav bar, table row striping, login card |
| Accent (10%) | `#a87f3d` (`text-gold-dark` / `bg-gold-dark`) | See "Accent reserved for" below |
| Destructive | `#e11d48` (`text-rose-600` / `bg-rose-600`) | Cancel/No-show confirmation dialogs, the "No-show" status tag text, destructive-action buttons, session/auth error banners |

**Accent reserved for** (explicit list — nothing else may use gold):

1. The primary "Log In" submit button on the login page (`bg-gold-dark hover:bg-gold text-white`)
2. The "Add Staff Member" submit button on the Owner-only add-staff screen
3. The left 4px status-indicator border on a **Confirmed** appointment block (the default, most common
   state) — `border-l-4 border-gold-dark`
4. A small filled-circle checkmark badge on a **Completed** appointment block's corner (does not
   replace the block's neutral card surface — Completed is not a new color, just a badge)
5. The active/selected segment of the Day/Week toggle, and the "Today" toolbar button
6. The currently-selected date in the date picker
7. Focus ring / focus border on form inputs (`focus:border-gold-dark`), matching `landing-page`'s
   `focus:border-gold` pattern adapted to the darker shade for light-surface contrast

Never use gold for: body text, disabled states, the Cancel/No-show quick-action icons (those are
neutral until pressed, then route into the destructive-red confirmation dialog), or decorative fills
outside the list above.

**Status color-coding for appointment blocks/chips** (DASH-04's separability requirement — Cancelled
and No-show must never share one visual treatment):

| Status | Block treatment |
|--------|------------------|
| Confirmed | `bg-surface-alt`, `border-l-4 border-gold-dark`, full opacity — the default look |
| Completed | Same as Confirmed, plus a small gold-filled checkmark badge in the block's top-right corner |
| Cancelled (hidden by default, D-08) | `bg-surface-alt/60` (muted), `border-l-4 border-border` (neutral gray, not gold, not red), time/client text `line-through`, a `text-muted` "Cancelled" label |
| No-show (hidden by default, D-08) | `bg-surface-alt/60` (muted), `border-l-4 border-border`, time/client text `line-through`, a `text-rose-600` "No-show" label — the only visual difference from Cancelled is this label's color and text, which is deliberate: front-desk staff scan for no-shows more urgently than routine cancellations |

## Additional Notes — Dashboard Component Patterns

Prescriptive shapes for the pieces this phase introduces, so the planner/executor don't have to invent
visual structure mid-implementation.

**Day view (D-05):** a CSS Grid with a sticky leftmost time-axis column (labels every 30 or 60 minutes,
Body-role text, `text-muted`) and one column per active stylist (`Label`-role header showing the
stylist's name, sticky at the top). Appointment blocks are absolutely/grid-positioned within a
stylist's column at `top = minutesSinceOpen × (20px / 15min)` and sized per the Spacing-Scale exception
above. A shared zone caption ("All times shown in salon local time (Myanmar Time)") sits once above
the grid, matching `landing-page`'s existing shared-caption pattern rather than repeating the zone on
every block.

**Appointment block anatomy:** client name (Body, semibold not needed — weight stays 400, size
differentiates it), service name (Body, `text-muted`), time range (Label, `text-muted`), and — space
permitting (blocks ≥40px tall) — the three quick-action icon buttons (Complete/Cancel/No-show) in a
row at the block's bottom edge, each a 24px icon in a 44px tap target. Clicking the block body (not an
icon) opens the detail panel.

**Week view (D-06):** 7 equal-width day columns (Monday-start), each a vertical stack of condensed
chips — one line per appointment: time + client + service, truncated with `text-ellipsis` if it
overflows. Chips use the same status color-coding as day-view blocks but as a left border only (no
badge/checkmark at this density). Clicking a day column header drills into that day's Day view;
clicking an individual chip opens the detail panel directly.

**Toolbar (D-07):** single row — prev/next chevron icon buttons, a "Today" button (gold-dark filled),
a native `<input type="date">` (styled to match the light theme, mirroring `landing-page`'s
`[color-scheme:dark]` trick but with `[color-scheme:light]`), the Day/Week segmented toggle, the "Show
cancelled & no-shows" switch, and the refresh button + "Updated Xm ago" caption on the far right.
Wraps to two rows on narrow viewports (D-17: phone-usable, not phone-optimized).

**Detail panel (DASH-02):** a right-side slide-over panel (desktop) that becomes a full-screen sheet on
narrow viewports — not a small centered modal, since it needs room for every field: client name,
phone/email, service, stylist, price, duration, created-at, current status tag, the status-audit line
(see Copywriting Contract), the email-failure caption (if applicable), and the same three quick-action
buttons as the block, full-size (not icon-only) with their labels visible.

**Confirmation dialogs (D-11):** a small centered modal (not the slide-over), Heading-role title
matching the action ("Cancel Appointment" / "Mark as No-Show"), the copy from the Copywriting Contract,
a destructive-red confirm button, and a neutral "Never mind" cancel button. Completed has no dialog —
clicking Complete applies the status change immediately with an inline success flash (e.g. a brief
checkmark pulse on the block), no modal at all.

**Login page:** centered card (`bg-surface-alt`, `rounded-2xl`, `p-8`, matching `landing-page`'s
`rounded-2xl` card radius convention) on the `bg-surface` page background, with the Display-role
"Staff Log In" heading, email + password fields (reusing `landing-page`'s `inputClass` shape but
recolored for the light theme: light border, dark text, `focus:border-gold-dark`), the primary CTA,
and an inline error message (destructive-red) below the form on failed login. No "forgot password" or
self-registration link — D-04 explicitly has no self-registration flow this phase.

**Add-staff screen (Owner-only, D-04):** same card-on-page layout as login, gated behind
`[Authorize(Roles = "Owner")]` server-side and a client-side role check that redirects Staff-role users
away. Fields: display name, email, password, role select (Owner/Staff). Submits to the Owner-only
endpoint; success shows the Copywriting Contract's success message and clears the form for adding
another staff member (does not navigate away, since adding staff one after another is the expected
flow at initial setup).

## Open Questions

Carried forward for the planner/executor to resolve or flag to the owner — not blocking this spec:

1. **Exact stylist-column width / minimum column count.** This spec assumes evenly-divided columns
   across all active stylists; if the salon has many stylists, the day grid may need horizontal
   scroll rather than ever-shrinking columns. Not specified in CONTEXT.md/RESEARCH.md; flagged as an
   executor-time decision once the seeded stylist count is known.
2. **Detail-panel vs. full detail route.** This spec assumes a slide-over panel (state-driven, no URL
   change) rather than a dedicated `/schedule/appointments/[id]` route. CONTEXT.md leaves the exact
   route shape to Claude's discretion; a panel keeps the staff member's grid scroll position, which
   this spec treats as the better default for a fast-paced front-desk tool.
3. **"Updated Xm ago" caption precision.** Recommends minute-level granularity ("Updated just now" /
   "Updated 1m ago"); not specified upstream. Low-risk, cosmetic-only if changed at implementation
   time.
4. **Add-staff role select default.** Recommends defaulting the role select to "Staff" (not "Owner"),
   since creating a second Owner is the rarer action — not specified upstream, flagged for the
   executor.
