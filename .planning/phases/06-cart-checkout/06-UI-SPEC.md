# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Scope: `landing-page/` only (SHOP-01..07) — a `/cart` page with line-item review and
stylist-recommended add-on suggestion chips (SHOP-07), a guest `/checkout` page that creates the
order and redirects to a Stripe Checkout Session (SHOP-02/06), and the post-payment return screens
`/checkout/success` (order-confirmation/pending-fulfillment state, SHOP-05) and `/checkout/cancel`.
Also adds the two entry affordances this phase is the first to need: an **Add to Cart** CTA on the
existing `/products/[slug]` aside and a **Cart** link with count badge in the shared `Navbar`.
This extends the **already-established** hand-rolled Tailwind design system from Phases 1/2/5 —
no design system reset, no new dependency, no shadcn. The client is a guest; `Order.ClientId` is
nullable (SHOP-06) and there is no account/login UI anywhere in this phase.

## Spacing Scale

Declared values (must be multiples of 4), identical to Phases 1/2/5:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, count-badge padding, stepper internal gaps |
| sm | 8px | Compact spacing (label-to-input `mb-2`, chip internal `gap-2`, stepper button-to-value `gap-1`) |
| md | 16px | Default form-field spacing, line-item row internal gaps (`gap-5`), grid gaps on tight rows |
| lg | 24px | Card padding (`p-7`), two-column gaps (`gap-6`), suggestion-chip section spacing |
| xl | 32px | Two-column cart/checkout layout gap (`gap-8`, mirrors `app/products/[slug]/page.tsx`) |
| 2xl | 48px | Section-level breathing room (suggestion chips below the line-item list, confirmation panel spacing) |
| 3xl | 64px | Page section vertical padding (`py-16`, matches `/products` and `/book`) |

Exceptions (pre-existing baseline; new components must remain consistent with them):

- **44px minimum touch target** (`h-11`/`w-11`) for quantity-stepper +/- buttons, the add-on chip "+ Add" affordance, and the cart icon link in the navbar — the same WCAG 2.5.5 floor Phase 2 declared for slot-grid cells; cart quantity steppers are exactly this kind of fast-tap-on-mobile control.
- **128px top padding** (`pt-32`) on every new `<main>` (`/cart`, `/checkout`, `/checkout/success`, `/checkout/cancel`) — reserves space for the fixed `Navbar`.
- **`gap-16` (64px)** remains the large-layout-split default where the `Contact.tsx` two-column pattern is mirrored; the cart/checkout two-column uses `gap-8` (xl) matching the product-detail layout instead.

## Typography

Four sizes, two weights for every *new* component — the Phase 2 discipline, with the catalog's price
treatment carried in as a baseline-inherited exception (see note below).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px (`text-xs`) | Regular (400) | 1.4 — uppercase, `tracking-wider`; cart eyebrow, suggestion-chip eyebrow, "Remove" link, out-of-stock/error micro-copy, navbar cart label |
| Body | 14px (`text-sm`) | Regular (400) | 1.5 — line-item metadata, order-summary rows, checkout form inputs/helper text, confirmation detail rows, empty/error state body |
| Heading | 18–20px (`text-lg` cart line-item name + section sub-labels / `text-xl` section and empty-state headings, confirmation heading) | Semibold (600) | 1.2–1.3 — same range Phase 5's card-title + aside-heading roles used |
| Display | 36px / 48–60px (`text-4xl md:text-5xl` via `SectionHeading`; `text-4xl md:text-6xl` on success/cancel `h1`, matching the product-detail `h1` class) | Regular (400), `font-serif` | 1.15 |

Weight notes:

- **Regular (400)** is the default for body copy, labels, and the serif Display role — no third default.
- **Semibold (600)** is reserved for emphasis: the primary CTA button labels, line-item product names, quantity values, section headings, empty-state headings.
- **`font-bold` (700) on price values is baseline-inherited, not a new component weight** — cart unit prices, line totals, subtotal, and the order Total reuse the catalog's exact `text-gold font-bold text-lg` treatment from `app/products/page.tsx` so the same product price reads identically in the catalog and the cart. Do not retrofit other `font-bold`/`font-medium` usages; do not add a third weight to new components.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#181410` (`bg-charcoal`) | Page background (`<main>`), base surface behind every screen |
| Secondary (30%) | `#241c15` (`bg-charcoal-light`) | Line-item rows, order-summary aside, checkout form card, suggestion-chip panel, confirmation/cancel panels — `border border-white/5 rounded-2xl`, mirrors `Contact.tsx`'s form card |
| Accent (10%) | `#d4af6a` (`text-gold` / `bg-gold`) | See "Accent reserved for" below — the single most disciplined constraint in this spec |
| Destructive | `rose-400` text (`#fb7185`) on `rose-500/10` background with `rose-500/20` border | Error banners only (`text-sm text-rose-400 bg-rose-500/10 border border-rose-500/20 rounded-xl px-4 py-3`, exact Phase 2 classes). Cart **Remove** is a quiet gray text link, NOT destructive red — removing a cart line is trivially reversible (the item is re-addable from the catalog) and carries no confirmation dialog (see Copywriting). |

**Accent reserved for** (explicit list — nothing else may use gold):

1. The navbar **Cart entry point**: cart icon (`text-gold`) and its count badge (`bg-gold text-charcoal text-xs font-semibold rounded-full`)
2. **Primary CTAs**: "Proceed to Checkout", "Continue to Payment", "Add to Cart", and the empty/cancel states' forward buttons — `bg-gold hover:bg-gold-dark text-charcoal font-semibold`, matching the Navbar "Book Now" pill and Phase 2's "Confirm Appointment" button. Buttons are `rounded-full px-6 py-3` (or the detail-aside `w-full` variant)
3. **Price values**: unit price, line total, subtotal, order Total — `text-gold font-bold text-lg` (exact catalog treatment)
4. Suggestion-chip **"Added ✓" feedback state**: chip flips to `border-gold text-gold bg-gold/10` with a gold `CheckIcon`
5. **Focus/active borders** on quantity-stepper buttons and checkout inputs (`focus:border-gold`, existing `inputClass` convention from Phase 2)
6. The success-page **checkmark icon + ring** (`bg-gold/20` circle, `text-gold` `CheckIcon`, exact Phase 2 confirmation pattern)
7. Gold eyebrow labels via `SectionHeading` (reused verbatim)

Never use gold for: body text, "Remove" links, disabled buttons/states, unselected suggestion chips, error text, out-of-stock badges, or decorative fills outside this list.

## UI Considerations

Applicable state considerations resolved: 13 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | cart page line-item list | ✅ covered | Zero items render the documented "Your Cart Is Empty" panel with a **Browse Products** CTA (mirrors `Services.tsx` / Phase 5 empty-state pattern) |
| empty | suggestion-chips section | ✅ covered | Zero recommendable suggestions omit the "Complete Your Routine" section entirely — same convention Phase 5 used for an unmapped recommendations section (a curation gap, not a user-facing error) |
| loading | cart page in-flight fetch | 🧪 backstop | Cart is a `"use client"` session-backed component, so the in-flight state is a local skeleton — `bg-charcoal border border-white/5 rounded-2xl p-7` pulse panels in place of line items — not a route-level `loading.tsx`. Phase 5's UI review (05-UI-REVIEW.md) scored the codebase down for having no loading/error boundaries anywhere under `landing-page/app/`; this phase must introduce the first one and a held-out visual check must confirm it renders on a cold cart fetch |
| loading | checkout submit / Stripe redirect | ✅ covered | "Continue to Payment" swaps to "Redirecting to payment…" and disables while the POST creates the order + Checkout Session and redirects — no spinner-only screen |
| error | cart load failure | ✅ covered | Inline rose banner "Couldn't Load Your Cart" with **Try Again**; cart retains its last-rendered state if any |
| error | checkout create failure | ✅ covered | Inline rose banner "Couldn't Start Checkout" with **Try Again**; order summary and cart contents stay intact — nothing is charged |
| error | add-to-cart failure / out-of-stock | ✅ covered | Add-to-cart network failure surfaces an inline rose alert on the detail aside; `stock === 0` renders the Add button disabled instead of allowing a doomed request |
| partial | checkout guest form | ✅ covered | "Continue to Payment" is disabled until Email is present and Zod-valid; field-level error text under Email on invalid input (PLAT-02 frontend convention) |
| populated | cart with line items | ✅ covered | Line-item rows + sticky Order Summary aside in the two-column `lg:grid-cols-[1fr_320px] gap-8` layout; quantity steppers capped at remaining `stock` |
| zero-one-many | cart line items | ✅ covered | Removing the last item transitions the page to the documented empty state; "1 item" vs "N items" summary micro-copy tracks the count |
| overflow | line-item name truncation | 🧪 backstop | Long product names in cart rows must not break row alignment — clamp with `line-clamp-2` on the name `p` and let the row `flex` wrap rather than overflow (Phase 5's grid-alignment backstop failed at execution; do not repeat: apply the clamp up front). Verify visually with the seeded 24-char `leave-in-repair-serum` name |
| overflow | order-summary rows | ✅ covered | Summary `dl` rows wrap normally; totals right-aligned via `justify-between`, no fixed-width columns to break |
| long-text | confirmation/fulfillment copy | ✅ covered | Success/cancel body copy is normal-flow centered text in `max-w-2xl` panels — wraps, no truncation |
| nav | navbar cart entry + count | ✅ covered | Cart link with icon; count badge hidden at 0, gold badge at 1+ — count is client-rendered from the cart session so it stays live as the cart mutates |
| not-found | `/checkout/success` without a valid order reference | ✅ covered | Missing/invalid order reference calls `notFound()`, reusing Next.js's existing 404 (matches `ServiceDetailPage`/`ProductDetailPage` convention) |

## Additional Notes — Component Patterns

Prescriptive shapes for the new pieces this phase introduces, so the planner/executor don't have to
invent visual structure mid-implementation.

**Navbar cart entry.** Add a `CartIcon` + "Cart" link to the shared `Navbar` (a `"use client"` component
already). Desktop: place it to the left of the "Book Now" pill (`hidden md:inline-flex items-center
gap-2 text-gray-300 hover:text-gold`); the icon is `text-gold`, the count badge sits top-right
(`bg-gold text-charcoal text-xs font-semibold w-5 h-5 rounded-full flex items-center justify-center`).
Mobile: add a "Cart" row to the open menu above "Book Now". The count is client-rendered from the cart
session (0 → no badge, N → gold badge) so it updates immediately when items are added. If the cart
session is missing/expired, the link still navigates to `/cart`, which renders its empty state.

**Product-detail aside — Add to Cart (new CTA on `/products/[slug]`).** Below the Price/Stock `dl` in
the existing sticky aside, add a quantity stepper + full-width `Add to Cart` button
(`w-full bg-gold hover:bg-gold-dark text-charcoal font-semibold text-sm px-6 py-3 rounded-full`).
Out of stock (`stock === 0`): the button renders disabled (`opacity-40 cursor-not-allowed`) under the
existing "Out of Stock" badge. On successful add: button label swaps to "Added ✓" with a gold
`CheckIcon` for ~2s, then reverts; the navbar count increments. A failed add renders the inline rose
alert inside the aside. This is the minimal SHOP-01 affordance; no add-to-cart on the catalog cards
(cards are whole-card `<Link>`s — see Open Questions).

**Cart page** (`/cart`, `"use client"`). Two-column `grid lg:grid-cols-[1fr_320px] gap-8 items-start`,
mirroring the product-detail layout. Main column: `SectionHeading` ("Your **Cart**"), then the
line-item list (`space-y-4`). Each row: `bg-charcoal-light border border-white/5 rounded-2xl p-5 md:p-7
flex items-center gap-5` — thumbnail (product `Image` `w-20 h-20 rounded-xl object-cover`, or the
existing `w-14 h-14 bg-gold/10 rounded-xl` Z-monogram when no `imageUrl`), then a column with name
(`text-lg font-semibold text-white`, `line-clamp-2`), unit price (gold, body size), and below the
quantity stepper; right side: line total (gold) + "Remove" text link. Below the list, the
suggestion-chips section (see next). Aside: sticky `Order Summary` card
(`bg-charcoal border border-white/5 rounded-3xl p-7 lg:sticky lg:top-28`, matching the product-detail
aside shell) — Subtotal / Total `dl` rows, full-width **Proceed to Checkout**, then "Continue Shopping".

**Quantity stepper.** `inline-flex items-center rounded-full border border-white/10` — a minus button
(`w-11 h-11`, `aria-label="Decrease quantity"`), the value (`min-w-8 text-center font-semibold`), a
plus button (`w-11 h-11`, `aria-label="Increase quantity"`). Real `<button>`s, 44px minimum, keyboard
and touch accessible. Min 1 (minus disabled at 1), max `stock` (plus disabled at stock). A server
409/validation error from an out-of-range update surfaces the inline rose banner and reverts the row
to the last known-good quantity.

**Suggestion chips (SHOP-07).** Section under the line-item list: heading "Complete Your Routine" +
subtitle, then `flex flex-wrap gap-3` of chips: `rounded-full border px-5 py-2.5 text-sm` (unselected
`border-white/10 text-gray-300`, exactly the Phase 2 stylist-chip anatomy) with the product name +
price (gold) and a "+" add affordance. Added → `border-gold text-gold bg-gold/10` + gold `CheckIcon` +
"Added"; out-of-stock → disabled (`opacity-40 cursor-not-allowed`). Section omitted entirely when no
suggestions resolve. Data source (same-category in-stock products vs. a seeded recommendation
mapping) is planner/executor discretion — see Open Questions.

**Checkout page** (`/checkout`, `"use client"`). Single centered panel
(`bg-charcoal-light border border-white/5 rounded-2xl p-7 md:p-10 max-w-2xl mx-auto`): "Checkout"
heading + subtitle, a compact order summary (each line: name × qty — line total; then Total in gold),
the contact form (Email required, Name optional — standard `inputClass` styling with
`focus:border-gold`), and a full-width **Continue to Payment** button. Submit: POST to create the
order + Checkout Session; on success `window.location.href = sessionUrl` and the button swaps to
"Redirecting to payment…" (disabled); on failure the inline rose banner "Couldn't Start Checkout".

**Order confirmation** (`/checkout/success`). Centered panel (`max-w-2xl mx-auto text-center`) with
the Phase 2 confirmation anatomy: gold ring + `CheckIcon` (`bg-gold/20` circle, `text-gold` check),
serif "Order Received" `h1`, body copy, then the detail rows (order number, item list, Total) and the
SHOP-05-honest fulfillment caption. No valid order reference → `notFound()`.

**Checkout cancel** (`/checkout/cancel`). Centered panel — "Checkout Cancelled" heading, body copy,
full-width **Return to Cart** gold button.

**Loading skeleton (first in the codebase).** The cart page's in-flight state is `bg-charcoal border
border-white/5 rounded-2xl p-7` pulse panels sized like line items, replacing the Phase 5 review's
blank-page behavior. Checkout submit uses the button-label swap, not a skeleton.

## Open Questions

Carried forward for the planner/executor to resolve or flag to the owner — not blocking this spec:

1. **Suggestion-chip data source (SHOP-07).** The visual contract (chips, add feedback, disabled
   out-of-stock) is locked here; the backend/planner question of *where* recommendations come from —
   same-category in-stock products vs. reusing a seeded mapping — is open. Same-category
   same-catalog products "not already in the cart, limited to ~4" is the lowest-dependency default
   consistent with the "no general-purpose recommendation engine" out-of-scope note in REQUIREMENTS.md.
2. **Email capture location.** This spec defaults to collecting Email + Name on `/checkout` before
   redirecting (the order needs a contact for the fulfillment email, and Stripe's hosted page can be
   prefilled via `customer_email`). If the executor instead delegates contact collection entirely to
   Stripe's Checkout Session, `/checkout` collapses to just the summary + **Continue to Payment** —
   either is contract-compliant; pick one and keep the order's contact populated from the same source.
3. **Add-to-cart on catalog cards vs. detail-only.** Default is detail-page-only (the catalog card is
   a whole-card `<Link>`; an inline add button would fight navigation). A card-level quick-add is a
   possible Phase 8 polish; do not build it here.
