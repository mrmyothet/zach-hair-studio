## Phase Goal

**As a** salon client, **I want to** browse the studio's services with their descriptions, durations, and prices, **so that** I can decide what to book.

> Frontend slice, part 2 of 2 — single source of truth. Migrates the last two static surfaces (homepage Services section + Contact dropdown) onto the shared API data layer and retires the static service data from `lib/data.ts` (D-14). After this plan the site says what it said before, but every service surface reads from one database-backed source.

<objective>
Point the homepage Services subset and the Contact form's service dropdown at the shared `fetchServices` data layer, wire the `?service={slug}` pre-selection (D-04), and delete the now-duplicate `services`/`serviceOptions` exports from `lib/data.ts` (D-14). This closes the single-source-of-truth loop without regressing visible content.

Purpose: One catalog source (CAT-03 single-source), no drift between homepage/catalog/booking (Pitfall 4).
Output: API-backed homepage Services subset, API-backed + pre-selectable Contact dropdown, and a trimmed `lib/data.ts`.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-09 | Tampering (crafted ?service value) | Contact preselect | low | mitigate | Preselect only applies when the query value matches a known slug in the fetched list; unknown values fall back to the default empty option (Task 2) |
| T-01-08 | Tampering (stored XSS via service name/price in options/cards) | Services/Contact render | medium | mitigate | React auto-escapes interpolated strings; no `dangerouslySetInnerHTML` (Tasks 1/2) |
| T-01-10 | Denial of Service (homepage build fails when API offline) | app/page.tsx fetchServices | low | mitigate | `fetchServices` returns an empty array on fetch failure (Plan 03 Task 1), so the homepage renders an empty Services state rather than failing the build |
</threat_model>
