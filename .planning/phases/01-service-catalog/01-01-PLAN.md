## Phase Goal

**As a** salon client, **I want to** browse the studio's services with their descriptions, durations, and prices, **so that** I can decide what to book.

> Backend vertical, part 1 of 2. This plan establishes the validated **domain contract** (the `Service` entity + DTOs + FluentValidation validators) and the repo's first **test harness**. Plan 02 turns this into a working, seeded, queryable API. The two together form the backend half of the catalog slice; Plans 03–04 add the browser UI.

<objective>
Create the repo's first xUnit test project and the `Features/Services/` domain model — entity, DTOs, extension mappers, and FluentValidation validators — following the `Features/Bookings/` analog exactly. Write the validator unit tests **first** (RED), then implement the model and validators to turn them green (GREEN). This activates PLAT-02's API-side validation layer and the `Service` entity backing CAT-03.

Purpose: Lock the domain contract and validation rules every later phase copies, with automated proof from day one (no test framework existed before).
Output: `ZachHairStudio.Api.Tests` project wired into the solution; `Service` entity + 3 DTOs + `ServiceExtensions` + 2 validators in `API/ZachHairStudio.Shared/Features/Services/`; passing validator tests.
</objective>
