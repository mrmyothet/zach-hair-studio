## Phase Goal

**As a** salon client, **I want to** browse the studio's services with their descriptions, durations, and prices, **so that** I can decide what to book.

> Frontend slice, part 1 of 2 — the visible browse capability. Consumes the live API from Plan 02 to deliver the public `/services` catalog and `/services/[slug]` detail pages as Server Components with ISR and Zod-validated responses. After this plan a real client can browse the catalog and open any service in the browser.

<objective>
Build the shared frontend data layer (`lib/services.ts` with Zod schemas + `lib/formatDuration.ts`) and the two public catalog routes as React Server Components. This delivers CAT-01 (browse list) and CAT-02 (detail page), and establishes the Zod response-validation pattern (PLAT-02 frontend, D-18).

Purpose: Make the catalog visible and browsable; set the RSC + ISR + Zod frontend template later phases copy.
Output: `/services` list page (category-grouped), `/services/[slug]` detail page (with booking CTA), a shared Zod-validated data module, and a shared duration formatter.
</objective>
